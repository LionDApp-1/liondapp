# 付费开发市场方案（首版设计）

2026-10-04 改版取代下文的全局预算优先排序：预算保留为意向和筛选条件，最新/最需要/最讨论按各自含义排序。需求与应用体验反馈、关注、测试意愿和作者结果见 `PRODUCT_REDESIGN_2026_10_ZH.md`。旧规则仅作历史记录。

## 结论

首版不提供用户之间的交易入口、不接收或保管项目开发款；“付费开发”只表示需求方填写的预算意向，不表示已付款或平台担保。此模式不代表已获 Solana Mobile 批准；最终以商店审核和适用规则为准。

## 首版范围

1. 需求可标记为“付费开发”或“免费诉求”；币种首版支持 SKR，USDT 等其他 SPL Token 后续增加。
2. “付费开发”使用醒目但克制的品牌色标签和金额胶囊，免费诉求使用中性色，避免暗示平台担保。
3. 付费开发需求始终排在免费诉求前，同一组内按金额从高到低，再按发布时间排序；金额不公开余额，只显示用户主动填写的预算。
4. 需求详情提供“联系需求方”入口，双方建立私信会话；聊天文本沿用统一内容审核、限流、举报和拉黑规则。
5. 对话只提供文字交流、举报、拉黑和消息删除能力，不提供报价单、付款按钮、订单、定金、押金或交易跳转。
6. 增加“打赏 LionDApp”入口，固定显示项目收款钱包和 SKR Mint；这是面向项目方的单独、自愿捐赠流程，不与付费开发需求混淆。
7. 用户主页展示公开资料、已发布需求和审核通过的已发布作品；私信、钱包余额和交易隐私不公开。

## 资金与争议规则（必须先定稿）

- 平台不提供用户之间的转账、托管、代收、代付、订单或保证金功能，也不承诺退款或交付结果。
- 预算字段必须标注为“预算意向”，不使用“赏金”“已付款”“已托管”“平台担保”等词。
- 需求状态使用 `open`、`in_progress`、`submitted`、`completed`、`cancelled` 等协作状态，不代表资金状态。
- 此次新增需求中，打赏 LionDApp 是唯一保留的转账场景；已有推荐位付费另行验收。打赏必须与付费开发需求分离，并在确认前显示收款地址、Mint、金额和不可逆提示。
- 上线前必须由熟悉中国、目标市场及加密资产业务的律师确认：服务条款、免责声明、打赏性质、制裁地区、未成年人、税务、个人信息和是否触发支付/虚拟资产服务许可。

## 开发顺序

1. 先做“付费开发/免费诉求”字段、颜色标签、排序、主页和私信 MVP。
2. 再做私信会话、消息审核、举报、拉黑和未读提醒。
3. 独立实现 LionDApp 打赏，并使用小额测试钱包在 Seeker 实机验收：错误地址、错误 Mint、金额确认、取消页面、重复签名和网络失败。
4. 完成法律文本、地区限制和风险提示后才开放打赏主网；用户之间的交易功能不进入首版。
