## 修复

首次 SBF 编译发现结算指令 `Settle::try_accounts` 的栈偏移 4,368 字节，超过 4,096 字节限制。工具仍然生成 `.so` 并返回成功，因此仅检查退出码会漏报。将结算中的 Config、Campaign、Entry 账户改为 Box 后，重编译没有栈超限诊断；账户布局、PDA、指令和资金规则保持一致。

新增 `scripts/verify-escrow.sh`，同时检查编译诊断、运行完整测试并记录源码/锁文件/产物 SHA-256。工具自动生成的临时程序密钥随临时目录删除，不作为部署身份。缺少 `.so` 时测试直接失败，不跳过用例。

## 实际运行覆盖

| 验证范围 | 检查结果 |
| --- | --- |
| 配置初始化 | 仅升级权限持有者能初始化；固定 Mint、手续费收款人；拒绝重复初始化及非六位精度 |
| 全额预存 | 奖励加额外 10% 费用转入 PDA 金库；余额不足、溢出或无效条件时回滚账户与转账 |
| 参与限制 | 名额上限、同钱包唯一、禁止发起者自测；已付名额不能再次支付给另一人 |
| 身份和账户约束 | 错误测试者、验收者、复核者、Mint、收款人及 ATA 被拒绝；正确数据但错误 PDA 的伪造记录也被拒绝 |
| 成果及验收 | 空报告哈希、缺少补充/拒绝理由不能推进状态；最多一次补充 |
| 截止及争议 | 提交、验收、申诉时间边界；验收超时的已提交成果不会自动失去资金保护；复核有权限检查 |
| 原子支付 | 测试者收完整奖励，费用单独支付；第二笔费用转账失败时第一笔奖励也回滚；拒绝重复结算 |
| 退款及退出 | 未结事项阻止退款；停止招募不取消已有奖励；未用余额退回发起者；重复退款/释放被拒绝 |

测试金额使用整数：每人奖励 `11,000,001` 最小单位，费用向上舍入为 `1,100,001`，两人全额预存 `24,200,004`。支付一人后，剩余 `12,100,002` 退回发起者。测试使用合成 SPL 代币，不是真实 SKR。
