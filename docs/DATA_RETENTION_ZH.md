# 数据长期保存与恢复

核查日期：2026-09-09。

## 当前结论

Cloudflare Worker + D1 + R2 能支撑长期运营，无需为了持久化更换技术栈。
D1 保存账户、需求、作品、评论和订单；R2 保存图片。手机卸载、会话过期、Worker 更新和重启不会清空这两种存储。

当前 D1 约 3.14 MB，19 张表。已经读取线上 R2 生命周期：只有默认“7 天后中止未完成的分片上传”，没有删除已完成图片的过期规则。

- 未删除的需求、作品、评论和关联图片没有按年龄自动删除的逻辑。
- 内容审核屏蔽只影响公开展示；旧违规内容原文仍供作者和后台核查。没有设置 deleted_at，不会进入 30 天清理。
- 用户主动删帖/删账户，或后台移除内容后，立即停止公开展示。既有定时任务在删除满 30 天后清空正文并清理关联 R2 图片。
- 登录令牌/登录挑战会过期，这是认证状态，不是帖子保存时间。
- 通知、已解决举报、审核事件和后台审计日志目前有 180 天保留策略；不能笼统宣称“所有类型的数据永不清理”。推荐到期只结束曝光，不删除作品。
- 官方商店目录是外部来源缓存：来源下架后可停止展示，不属于用户主动发布的社区内容。
- 列表有每次 30/50/200 条等查询上限。未出现在首屏不等于被数据库删除；用户量扩大前应补充游标分页。

已新增真实 SQLite 回归：2000 年创建且未删除的需求、作品及图片经历清理仍保留；只清理之前明确删除且满 30 天的作品及图片。

## 持久化不等于灾备

D1 自带 Time Travel 的窗口为 Free 7 天、Paid 30 天。这个窗口限制的是“能回滚到多久以前”，不是正文只能存 7/30 天。

本次尚未建立独立、定时且经过恢复演练的备份系统，也未确认账户付费计划；不能把自带恢复能力称为永久灾备。

建议首版上架前完成：

1. 确认账户计划、D1 容量和每日读写额度告警，接近配额前升级或分库。
2. 每日将 D1 快照导出至私有备份桶，保留 7–30 天滚动版本；记录导出时间、大小和校验值。失败要通知管理员。
3. 单独备份 R2 媒体；D1 SQL 导出不包含图片字节。备份存储与业务桶分开，避免误删波及同一份副本。
4. 每月至少将一份备份恢复到隔离测试数据库/桶，核对内容数量、图片、作者关联、删除标记和实际可读性。
5. 恢复时执行删除记录对账，避免重新公开用户已删除或后台已移除的内容。备份生命周期也必须符合隐私政策的删除期限。
6. 维护 Cloudflare 账户恢复方式、账单和域名续费。服务停用、账户删除、达到容量限制、误操作及账单问题都不是技术栈能无限兜底的情况。

不要直接在生产 D1 上尝试恢复命令：原地恢复会覆盖当时以后的数据。先在隔离环境演练。

## 2026-09-16 私信扩展

未删除的私信没有自动到期清理。作者撤回或删除账户后，对双方立即隐藏正文；30 天后清除正文，但未结案的举报需保留证据，结案后下一次保留任务再清除。已处理私信举报保留 180 天。对话元数据与撤回占位仍保留。私信不是端到端加密，发送前会经 Workers AI 审核。
